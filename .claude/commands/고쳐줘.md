문제: $ARGUMENTS

**바로 고치지 않는다.** "이상해", "안 돼", "깨졌어"처럼 무엇이 어떻게 다른지 모르는 말만으로는 작업하지 않는다.

1. 위 문제에서 아래 세 가지를 찾는다. 하나라도 비어 있거나 애매하면, 그 칸만 골라 사용자에게 먼저 묻고 답을 기다린다.
   - **어디가**: 화면(홈 / 매물 / 비교 리포트 / 우리 기준 / 3D 집 보기 / 바텀시트), 기능, 매물 이름
   - **지금은**: 실제로 보이는 값이나 모습 (숫자, 문구, 캡처, 콘솔 에러)
   - **원래는**: 기대한 값과 그 근거 (도면 치수, 계산식, 이전 버전·커밋, 디자인 가이드)
   - 묻는 예: "어느 화면의 어떤 매물인가요? 지금 화면에 보이는 숫자와, 원래 나와야 할 숫자를 알려 주세요. 근거(계산식·도면 치수·이전 버전)가 있으면 같이 주세요."
2. 세 가지가 채워지면 한 번에 정리해서 보여준다.
   ```
   어디가: ...
   지금은: ...
   원래는: ... (근거: ...)
   ```
3. 고치기 전에 재현한다. 데이터 없는 별도 주소(localhost:8766)나 임시 프로필에서 같은 조건을 만들어 "지금은"이 실제로 보이는지 확인한다. 재현이 안 되면 그 사실과 시도한 조건을 알리고 추가 정보를 묻는다.
4. 증상이 아니라 원인을 고친다. 같은 원인을 쓰는 다른 화면도 함께 확인한다. 작업 전 index.html 을 백업한다.
5. 고친 뒤 "원래는"의 값이 나오는지 같은 조건으로 다시 확인하고, 콘솔 에러와 데스크톱 1280 / 모바일 390 화면을 본다.
6. 보고: 원인 한 줄, 바뀐 파일, 전/후 값 표, 남은 문제. 커밋·push 는 사용자 확인 후에만 한다. 실제 저장 데이터('newlywed-home-v1')는 덮어쓰지 않는다.
