할 일: $ARGUMENTS

**바로 코드를 쓰지 않는다.** 먼저 관련 코드와 문서(`index.html`, `docs/design/`, `design-guidelines.md`, `README.md`)를 읽어 지금 구조를 파악한 뒤, 아래 일곱 칸을 채워 보여주고 사용자의 확인을 기다린다. 확인 전에는 파일을 만들거나 고치지 않는다(읽기·조사는 해도 된다).

칸을 채울 때:
- 추측한 것은 "가정:"으로 표시하고, 답이 갈리는 결정은 맨 아래 "확인할 것"에 질문으로 모은다(최대 3개).
- 새 기능이나 로직 변경이면 "단계" 앞에 mermaid 흐름도를 붙인다(전역 규칙: 확정되면 `docs/design/<기능명>.md`에 저장).
- 지금 코드로 어려운 부분, 숫자가 순환논리가 되는 부분(예: 자동 축척으로 맞춘 면적을 다시 면적과 비교)처럼 결과를 믿기 어려운 곳은 숨기지 말고 적는다.

```
## 지시서 — <할 일 한 줄>

### 1. 목표
끝났을 때 화면에서 무엇이 보여야 하는지 한두 문장.

### 2. 조건
고정값과 단위. 기본으로 넣을 것:
- 금액 만원, 면적 ㎡, 시간 분, 거리 m
- 저장 키 'newlywed-home-v1' 유지, 예전 데이터는 migrate()로 읽힘
- 화면 폭 기준: 데스크톱 1280, 모바일 390 (시트 전환 768px)
- 그 밖에 이 작업에 필요한 고정값

### 3. 단계
3~6단계. 단계마다 "→ 확인:"으로 그 단계가 끝났는지 보는 방법.

### 4. 규칙
- 작업 전에 index.html 을 index_vN_backup.html 로 백업
- design-guidelines.md 의 토큰만 사용 (새 값은 먼저 그 파일에 추가)
- 기존 기능 유지: 등록·수정·삭제, 점수·순위, 차트, 리포트, 평면도 인식, 3D·가구, 바텀시트, 내보내기/불러오기
- 단일 HTML 파일 + CDN, 빌드 없음
- 그 밖에 이 작업만의 규칙

### 5. 검수
- 콘솔 에러 0건, 계산 자체검사(selfTest) 통과
- 시나리오별 결과 (입력 → 기대값 → 실제값)
- 데스크톱 1280 / 모바일 390 스크린샷 → screenshots/after_vN_*
- 390px 가로 넘침 없음
- 테스트는 데이터 없는 별도 주소(localhost:8766)·임시 프로필에서만, 끝나면 실제 데이터 지문(크기·해시)이 그대로인지 확인

### 6. 보고
- 바뀐 파일 목록과 한 줄 설명
- 테스트 표 (항목 | 데스크톱 | 모바일 | 결과)
- 남은 문제·한계, 다음에 할 만한 것
- 커밋 메시지 초안 (Claude 서명 줄 없이)

### 7. 제한
- 실제 저장 데이터('newlywed-home-v1')를 덮어쓰거나 지우지 않는다
- 외부 패키지 설치·새 CDN 라이브러리 추가는 먼저 묻는다
- 사용자 확인 없이 커밋·push 하지 않는다
- 사용자의 네이버 평면도 이미지를 공개 저장소·커밋된 스크린샷에 넣지 않는다 (git 제외 폴더 screenshots/process/ 만)
- 그 밖에 이 작업에서 하지 말 것

### 확인할 것
1. ...
```
