# 도면 분석 보드 (v6, 2026-11-03)

3D 집 보기의 새 탭 "도면 분석". 평면도 인식 결과(벽 mask · 집 안/밖 · 설비)만으로 조닝·동선·채광을 코드로 그리고, 4장을 보드 PNG 한 장으로 모은다. 외부 이미지 생성 없음(Canvas·Three.js). 백업: `index_v5_backup.html`.

```mermaid
flowchart TD
  P[평면도 인식 결과<br/>벽 mask · 집 안/밖 · 설비 · 축척] --> Z{2D 도면? plan.mono = 0}
  Z -- 2D --> C[칸마다 바닥 색 분류 floorKind<br/>원목·카운터 → 생활 · 연베이지 → 수면 · 하늘색 → 욕실 · 무채 회색 → 현관·수납<br/>글자·흰 칸은 가까운 구역으로 채움]
  Z -- 3D 렌더 --> Z3[조닝 생략 안내 · 벽으로 나뉜 공간과 동선만]
  C --> S[같은 종류로 이어진 덩어리 = 공간 · 0.5㎡ 미만 조각은 이웃에 붙임]
  Z3 --> S
  S --> T[공간별 바닥 면적 + 벽 면적의 절반 = 벽 중심선 기준 합계<br/>입력한 전용면적 대비 % · 10% 넘으면 경고]
  S --> E[현관: 직접 찍은 곳 plan.entry, 없으면 바깥과 이어진 문 틈(회색 바닥 우선)]
  E --> R[8방향 최단 경로(모서리 안 가로지름) · 벽·설비 피함 → 공간 가운데까지 거리 m]
  L[매물 방향 facing + 창 쪽 벽 plan.winSide(기본: 평면도 아래쪽)] --> O[planRot = 창 쪽 벽 각도 − 방위]
  O --> H[해 위치 sunPos: 서울 위도 37.5° · 하지/동지 · 태양시 = KST − 32분]
  H --> G[3D 집 보기 장면 재사용 · 이 탭에서만 sun.castShadow · 그림자 판(ShadowMaterial, renderOrder −1)]
  T --> B[보드 2400×1800: 01 평면(벽 검게) · 02 조닝 · 03 동선 · 04 3D 사선뷰]
  R --> B
  G --> B
```

- 면적 비교: 전용면적은 벽 중심선 기준이라 "방 바닥 합계 + 벽 면적의 절반"과 비교한다(사용자 결정). 자동 축척은 전용면적에 맞춘 값이라 비교가 순환하므로, 화면에 "치수 맞추기를 하면 실제로 비교돼요"라고 알린다.
- 방향: 기본은 "평면도 아래쪽이 바라보는 방위". '창 쪽 벽 찍기'로 누른 바깥벽(네 방향 중 바깥이 가장 가까운 쪽)을 매물마다 `plan.winSide`에 저장하고, 화면에 지금 기준을 표시한다.
- 검수 결과(도면 치수 축척): 예시 투룸 44.37㎡ vs 전용 45㎡(−1.4%), 301호 37.93㎡ vs 38.51㎡(−1.5%). 301호는 가로 9.8m로 맞췄을 때 세로가 4.11m(도면 3.9m)로 잡혀, 바깥 경계 인식에 문 밖 여닫이 호 등이 섞이는 것으로 보인다(한계).
- 예시 평면도: `scripts/verify/make_plan_sample_color.py` → `samples/plan_sample_color.png` (투룸, 벽 중심선 9.0 × 5.0m). 회색·검정 비율 0.075로 2D 판별 기준(0.10) 아래가 되게 여백·회색 밝기를 맞췄다.
