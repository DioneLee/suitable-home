# 여러 탭 저장 충돌 막기 (2026-11-03)

증상: 예전 버전이 열린 채 남아 있던 탭이 메모리의 옛 데이터를 저장해, 실제 사이트 데이터(매물 3곳 + 평면도 88KB)가 지도 기능 직후 형식의 839바이트로 덮어써졌다.
원인: 앱이 데이터를 메모리에 들고 화면을 그릴 때마다 통째로 저장한다 → 탭이 둘이면 마지막에 저장한 탭이 이긴다. 백업: `index_v6_backup.html`.

```mermaid
flowchart TD
  L[load: lastSaved = 저장소 원본] --> R[render → save]
  R --> C{저장소 == lastSaved ?}
  C -- 같음 --> W[JSON 이 바뀌었을 때만 쓰기 · lastSaved 갱신]
  C -- 다름: 다른 탭이 썼다 --> A{입력 데이터가 같고<br/>지도 캐시 geo·routes 만 다른가}
  A -- 예 --> M[캐시 합치기 · lastSaved = 저장소 → 쓰기 계속]
  A -- 아니오 --> S[낡은 탭: 저장 멈춤]
  E[storage 이벤트 (첫 화면 이후만)] --> A2{입력 데이터 같음?}
  A2 -- 예 --> M2[캐시 합치기 · lastSaved = 새 값]
  A2 -- 아니오 --> S
  S --> V{이 탭이 보이는 중?}
  V -- 예 --> B[안내 띠: 다른 탭에서 바뀜 · 새로 불러오기]
  V -- 아니오(뒤에 숨은 탭) --> H[다시 보일 때 자동으로 새로 열기]
```

- 첫 화면을 그리기 전(`booted` 전)에 온 storage 이벤트는 무시하고 첫 save() 의 비교에 맡긴다 — 동시에 연 탭이 아직 TYPE 글자 등을 채우기 전에 받은 알림을 충돌로 오판하지 않게.
- 한계: 이 보호 코드가 없는 **예전 버전이 이미 열려 있는 탭**은 여전히 덮어쓸 수 있다 → 오래 열어 둔 탭은 새로고침해서 쓴다. 저장된 데이터는 JSON 내보내기로 따로 보관해 두는 것을 권한다.
- 검증: localhost:8766 에서 동시에 연 두 탭 ×3회(처음엔 둘 다 정상, 실제 변경 시 낡은 탭 안내·저장 차단), 숨은 탭 다시 보일 때 자동 새로 열기, 탭 하나일 때 추가·수정·삭제·설정·평면도 저장.
